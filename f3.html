Threats and Vulnerabilities

Think of your network like your house:

🔓 Vulnerability

A weakness that can be exploited. Like leaving your front door unlocked.

Example: Using "admin/admin" as your router password

⚡ Threat

A potential danger that exploits a vulnerability. Like a burglar trying doors.

Example: A hacker scanning for default passwords

Common Network Threats (with BrewNet examples)

🎣

Phishing

A BrewNet employee gets an email: "Your Google account is locked! Click here." They click, enter their password — now the attacker has their credentials.

🦠

Malware / Ransomware

An employee plugs in a USB found in the parking lot. It installs ransomware that encrypts the POS database. "Pay ₱50,000 in Bitcoin to unlock."

👤

Man-in-the-Middle (MitM)

A customer on BrewNet's open Wi-Fi intercepts data between the cashier's tablet and the router, capturing credit card transactions.

🌊

DDoS Attack

A competitor floods BrewNet's online ordering website with fake traffic, making it unreachable for real customers during peak hours.

🔑

Brute Force Attack

An attacker uses software to try thousands of password combinations on BrewNet's admin panel until one works: "coffee123".

🕵️

Insider Threat

A disgruntled ex-employee still has the Wi-Fi password and remote access credentials. They log in and delete sales records.

Basic Security Controls

Security controls are the locks, alarms, and cameras of your network. Here's what BrewNet needs:

🔥

1. Firewall

What: A digital bouncer that checks every packet entering or leaving your network against a set of rules.

BrewNet fix: Enable the router's built-in firewall. Block all incoming traffic except ports 80 (HTTP) and 443 (HTTPS) for the ordering system.

🔐

2. Strong Passwords & Authentication

What: Complex, unique passwords + multi-factor authentication (MFA). Think: password + SMS code.

BrewNet fix: Change router password from "admin" to a 12+ character mix. Enable MFA on the POS admin panel.

📡

3. Wi-Fi Encryption (WPA3/WPA2)

What: Encrypts data traveling over Wi-Fi so eavesdroppers see gibberish instead of passwords.

BrewNet fix: Switch from open Wi-Fi to WPA2-Enterprise for staff devices. Create a separate guest network for customers.

🔄

4. Regular Updates & Patching

What: Software vendors constantly fix vulnerabilities. Updates close those holes.

BrewNet fix: Enable auto-updates on the router firmware, POS software, and all employee devices.

📋

5. Access Control Lists (ACLs)

What: Rules that decide WHO can access WHAT. Like giving different keys to different employees.

BrewNet fix: Only the manager's laptop can access the router admin page. Cashiers can only reach the POS system.

💾

6. Backup & Recovery

What: Regular copies of important data stored separately, so ransomware can't hold you hostage.

BrewNet fix: Automated nightly backup of POS data to a cloud service. Test restore monthly.

🗺️ Quick Reference: Threat → Control Mapping

Threat Vulnerability Exploited Security Control
Phishing Human error / no training Security awareness + MFA
Malware Unpatched systems / USB Updates + Antivirus + Policy
MitM Open/unencrypted Wi-Fi WPA2/WPA3 encryption
DDoS No traffic filtering Firewall + Rate limiting
Brute Force Weak passwords Strong passwords + Lockout
Insider Threat No access review ACLs + Offboarding policy

All devices on 192.168.1.0/24 subnet

Step-by-Step Instructions

Part 1: Build the Topology (10 min)

1

Open Packet Tracer → New Project

File → New or Ctrl+N

2

Add devices from the bottom panel

• Network Devices → Routers → 1841 (drag to workspace)

• Network Devices → Switches → 2960 × 2

• End Devices → PC × 2, Laptop × 1

3

Connect with cables

• Router Fa0/0 → Switch0 Fa0/1 (Copper Straight-Through)

• Router Fa0/1 → Switch1 Fa0/1 (Copper Straight-Through)

• Switch0 Fa0/2 → PC-Manager (Copper Straight-Through)

• Switch0 Fa0/3 → PC-Cashier (Copper Straight-Through)

• Switch1 Fa0/2 → Laptop-Guest (Copper Straight-Through)

4

Rename devices

Click each device → Config tab → Display Name. Use: Router0, Switch-Staff, Switch-Guest, PC-Manager, PC-Cashier, Laptop-Guest

Part 2: Configure IP Addresses (10 min)

5

Configure the Router interfaces

Click Router0 → CLI tab → Type these commands:

enable

configure terminal

interface fa0/0

ip address 192.168.1.1 255.255.255.128

no shutdown

exit

interface fa0/1

ip address 192.168.1.129 255.255.255.128

no shutdown

exit

6

Configure PC-Manager

Click PC-Manager → Desktop tab → IP Configuration

IP: 192.168.1.10

Subnet: 255.255.255.128

Gateway: 192.168.1.1

7

Configure PC-Cashier

IP: 192.168.1.20

Subnet: 255.255.255.128

Gateway: 192.168.1.1

8

Configure Laptop-Guest

IP: 192.168.1.200

Subnet: 255.255.255.128

Gateway: 192.168.1.129

Part 3: Apply Security Controls (15 min)

9

Set a strong router password

On Router0 CLI:

enable

configure terminal

enable secret Br3wN3t$ecure!

line console 0

password C0ns0le@2024

login

exit

line vty 0 4

password R3m0te#Acc3ss

login

exit

service password-encryption

💡 "service password-encryption" encrypts all plaintext passwords in the config file

10

Create an Access Control List (ACL)

Block guest network from accessing staff network:

access-list 100 deny ip 192.168.1.128 0.0.0.127 192.168.1.0 0.0.0.127

access-list 100 permit ip any any

interface fa0/1

ip access-group 100 in

exit

💡 This means: "Anything from guest network trying to reach staff network → DENIED"

11

Configure a login banner

banner motd #WARNING: Unauthorized access is prohibited!#

💡 Legal protection — warns unauthorized users they're being monitored

12

Save your configuration

end

copy running-config startup-config

Part 4: Test & Verify (5 min)

13

Test: Staff can ping each other

PC-Manager → Desktop → Command Prompt

ping 192.168.1.20

✅ Expected: Reply from 192.168.1.20

14

Test: Guest CANNOT ping staff

Laptop-Guest → Desktop → Command Prompt

ping 192.168.1.10

❌ Expected: Request timed out (BLOCKED by ACL!)

15

Verify password protection

Close and reopen Router0 CLI. You should be prompted for a password.

✅ Expected: "User Access Verification" prompt + banner message

📖 The Incident Report

On March 15, BrewNet Café's manager arrived to find the POS system displaying a ransomware message demanding ₱50,000 in Bitcoin. Here's what the investigation revealed:

Finding 1: Weak Credentials

The router admin panel was accessible at 192.168.1.1 with username "admin" and password "admin". It had never been changed since installation 2 years ago.

Finding 2: Open Wi-Fi

The café's Wi-Fi had no password. Both customers and staff devices connected to the same network. There was no separation between guest and business traffic.

Finding 3: Phishing Email

A cashier received an email appearing to be from "Google Security" asking them to verify their account. They clicked the link on the POS computer and entered their password. Logs show the attacker used these credentials to access the router remotely.

Finding 4: No Backups

The POS database had not been backed up in over 6 months. All recent sales data, inventory records, and customer information were encrypted by the ransomware.

Finding 5: Outdated Firmware

The router was running firmware from 2021 with 3 known critical vulnerabilities. The POS software hadn't been updated in 8 months.

💰 Total Damage

₱50,000 ransom (unpaid) + ₱60,000 lost revenue (2 days closed) + ₱40,000 IT recovery costs = ₱150,000 total loss
