What is a VLAN?

A Virtual Local Area Network (VLAN) is a logical grouping of network devices on one or more LANs that are configured to communicate as if they were on the same physical network segment, regardless of their physical location.

Traditional Network

All devices on same physical segment share bandwidth and broadcast domain

VLAN Network

Devices logically separated into isolated broadcast domains for efficiency

Why Use VLANs?

🔒

Enhanced Security

Isolate sensitive departments (HR, Finance) from general network traffic

⚡

Improved Performance

Reduce broadcast traffic and congestion by limiting broadcast domains

💰

Cost Reduction

No need for additional physical networks or routers

🎯

Logical Organization

Group users by department or function regardless of physical location

📊

Simplified Management

Easier user moves, adds, and changes without rewiring

VLAN Concepts Explained

1. VLAN ID (VLAN Tag)

Each VLAN is identified by a unique number from 1 to 4094:

  • • VLAN 1: Default VLAN on all switches (cannot be deleted)
  • • VLANs 2-1005: Standard VLANs (normal range)
  • • VLANs 1006-4094: Extended VLANs (limited support)

2. Access Ports

Ports that connect to end devices (computers, printers, phones):

interface FastEthernet 0/1
switchport mode access
switchport access vlan 10

This port now belongs to VLAN 10 and only accepts untagged traffic

3. Trunk Ports

Ports that carry traffic from multiple VLANs (switch-to-switch or switch-to-router):

interface GigabitEthernet 0/1
switchport mode trunk
switchport trunk allowed vlan 10,20,30

This port carries tagged frames for VLANs 10, 20, and 30 to other network devices

4. VLAN Tagging (802.1Q)

When trunk ports carry VLAN traffic, each frame is tagged with a VLAN ID so devices know which VLAN it belongs to:

Frame: [Source MAC] [VLAN Tag: 20] [Dest MAC] [Payload]

↓ Switch reads tag ↓
"This frame belongs to VLAN 20 - forward to VLAN 20 ports only"

5. Native VLAN

The VLAN whose frames are sent untagged on a trunk port (usually VLAN 1):

switchport trunk native vlan 99

Step-by-Step VLAN Configuration

Example Scenario:

Create VLANs for a company with 3 departments and configure inter-VLAN routing:

VLAN 10 - HR Department (10.0.10.0/24)

VLAN 20 - Finance Department (10.0.20.0/24)

VLAN 30 - IT Department (10.0.30.0/24)

1

Create the VLANs on Switch

switch# configure terminal
switch(config)# vlan 10
switch(config-vlan)# name HR
switch(config-vlan)# exit
switch(config)# vlan 20
switch(config-vlan)# name Finance
switch(config-vlan)# exit
switch(config)# vlan 30
switch(config-vlan)# name IT
switch(config-vlan)# exit

✓ Three VLANs created with descriptive names

2

Assign Access Ports to VLANs

! Configure HR computers on ports 1-5
switch(config)# interface range fa0/1 - 5
switch(config-if-range)# switchport mode access
switch(config-if-range)# switchport access vlan 10
switch(config-if-range)# exit
! Configure Finance computers on ports 6-10
switch(config)# interface range fa0/6 - 10
switch(config-if-range)# switchport mode access
switch(config-if-range)# switchport access vlan 20
switch(config-if-range)# exit
! Configure IT computers on ports 11-15
switch(config)# interface range fa0/11 - 15
switch(config-if-range)# switchport mode access
switch(config-if-range)# switchport access vlan 30
switch(config-if-range)# exit

✓ Computers assigned to appropriate VLANs based on department

3

Configure Trunk Ports (Switch to Router)

! GigabitEthernet 0/48 connects to router
switch(config)# interface gi0/48
switch(config-if)# switchport mode trunk
switch(config-if)# switchport trunk allowed vlan 10,20,30
switch(config-if)# switchport trunk native vlan 99
switch(config-if)# exit

✓ Trunk port configured to carry all VLANs to router

4

Save Configuration

switch(config)# exit
switch# copy running-config startup-config

✓ Configuration saved permanently

Verify VLAN Configuration:

switch# show vlan brief
VLAN Name Status Ports
---- ----- ------ ------------------------------------------
10 HR active fa0/1,fa0/2,fa0/3,fa0/4,fa0/5
20 Finance active fa0/6,fa0/7,fa0/8,fa0/9,fa0/10
30 IT active fa0/11,fa0/12,fa0/13,fa0/14,fa0/15

Inter-VLAN Routing Configuration

By default, VLANs cannot communicate with each other. You need a router to route traffic between VLANs. There are two methods:

Method 1: Router-on-a-Stick (ROAS)

One router interface connects to a trunk port on the switch, handling all VLAN traffic via sub-interfaces.

[VLAN 10] ──→ Switch ←─── Router ←─→ Internet

[VLAN 20] ──→ (Trunk) ←─── (Sub-interfaces)

[VLAN 30] ──→ Port ←──→ Gi0/0.10, Gi0/0.20, Gi0/0.30

Configuration Example:

! Configure VLAN 10 sub-interface
router(config)# interface gi0/0.10
router(config-subif)# encapsulation dot1Q 10
router(config-subif)# ip address 10.0.10.1 255.255.255.0
! Configure VLAN 20 sub-interface
router(config)# interface gi0/0.20
router(config-subif)# encapsulation dot1Q 20
router(config-subif)# ip address 10.0.20.1 255.255.255.0
! Configure VLAN 30 sub-interface
router(config)# interface gi0/0.30
router(config-subif)# encapsulation dot1Q 30
router(config-subif)# ip address 10.0.30.1 255.255.0

Now HR (VLAN 10) can ping Finance (VLAN 20) by routing through the router!

Method 2: Layer 3 Switch

A Layer 3 Switch has built-in routing capabilities, making it more efficient than a router.

! Enable routing on switch
switch(config)# ip routing
! Configure VLAN interface IP addresses
switch(config)# interface vlan 10
switch(config-if)# ip address 10.0.10.1 255.255.255.0
switch(config-if)# no shutdown
switch(config)# interface vlan 20
switch(config-if)# ip address 10.0.20.1 255.255.255.0
switch(config-if)# no shutdown

The Layer 3 Switch automatically routes between VLANs - much simpler!

Test Inter-VLAN Connectivity:

! From HR computer (10.0.10.5) ping Finance (10.0.20.5)
C:\> ping 10.0.20.5
Pinging 10.0.20.5 with 32 bytes of data:
Reply from 10.0.20.5: bytes=32 time=2ms TTL=63
Reply from 10.0.20.5: bytes=32 time=1ms TTL=63
✓ Successfully ping between VLANs!
