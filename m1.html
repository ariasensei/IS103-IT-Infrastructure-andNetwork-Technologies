Why is Subnetting Important?

✓

Efficient IP Address Utilization

Avoid wasting IP addresses by dividing large networks into smaller, manageable subnets

✓

Improved Network Security

Isolate network segments, limit broadcast domains, and control traffic between departments

✓

Better Network Performance

Reduce broadcast traffic and congestion by limiting the size of broadcast domains

✓

Flexible IP Address Management

Use VLSM to allocate variable-sized subnets based on actual requirements of each department

✓

Simplified Network Expansion

Easy to add new subnets and departments without redesigning the entire network

✓

Hierarchical Routing

Route summarization reduces routing table size and improves routing efficiency

Key Concepts to Master

Subnet Mask

Determines which portion of an IP address is the network and which is the host

Network Address

First address in a subnet; all host bits are set to 0

Broadcast Address

Last address in a subnet; all host bits are set to 1

CIDR Notation

Compact representation like /24 showing the number of network bits

Step-by-Step Subnetting Guide

1

Understand Your Network Requirements

Before subnetting, determine:

  • • How many subnets do you need?
  • • How many hosts per subnet?
  • • What is your starting IP address and class?
2

Convert to Binary

Convert the host octet to binary to visualize which bits to borrow:

Example: 192.168.1.0/24 Subnet Mask: 255.255.255.0 In Binary: 11111111.11111111.11111111.00000000
3

Calculate Bits to Borrow

Use the formula: 2^n = number of subnets

Example: Need 4 subnets 2^2 = 4 subnets Therefore, borrow 2 bits from the host portion New mask: /26 (24 + 2)
4

Calculate Subnet Increment

The increment between subnets = 2^(8-borrowed bits)

Example: Borrowed 2 bits from last octet Increment = 2^(8-2) = 2^6 = 64 Subnets will be: 0, 64, 128, 192
5

List All Subnet Addresses

Generate complete subnets with network, usable hosts, and broadcast addresses:

Subnet 1: 192.168.1.0/26 Network: 192.168.1.0 First Host: 192.168.1.1 Last Host: 192.168.1.62 Broadcast: 192.168.1.63 Subnet 2: 192.168.1.64/26 Network: 192.168.1.64 First Host: 192.168.1.65 Last Host: 192.168.1.126 Broadcast: 192.168.1.127

✨ Complete Subnetting Example

Scenario: You have 172.16.0.0/22 and need to create 8 subnets

Step 1: Calculate bits needed

2^3 = 8 subnets → Need to borrow 3 bits

Step 2: New subnet mask

/22 + 3 bits = /25

255.255.254.0 → 255.255.255.128

Step 3: Calculate increment

We borrowed 3 bits from the last octet

Increment = 256 ÷ 8 = 32

Step 4: List all 8 subnets

Subnet 0: 172.16.0.0/25 (Hosts: .1 - .126)

Subnet 1: 172.16.0.128/25 (Hosts: .129 - .254)

Subnet 2: 172.16.1.0/25 (Hosts: .1 - .126)

Subnet 3: 172.16.1.128/25 (Hosts: .129 - .254)

Subnet 4: 172.16.2.0/25 (Hosts: .1 - .126)

Subnet 5: 172.16.2.128/25 (Hosts: .129 - .254)

Subnet 6: 172.16.3.0/25 (Hosts: .1 - .126)

Subnet 7: 172.16.3.128/25 (Hosts: .129 - .254)

VLSM (Variable Length Subnet Masking)

What is VLSM? A technique that allows different subnets to have different subnet masks, so you can allocate IP addresses more efficiently based on the actual needs of each network segment.

Why VLSM is Better Than Fixed Subnetting

❌ Fixed Subnetting Waste

All subnets same size = wasted addresses in small subnets

Example: Give 64 IPs to a 2-person office

✅ VLSM Efficiency

Custom subnet sizes = perfect fit for each department

Example: Give /30 (4 IPs) to 2-person office

📋 VLSM Real-World Scenario

Your company has 192.168.0.0/22 (1024 hosts) and needs to subnet it for:

  • • HR Department: 250 hosts
  • • IT Department: 120 hosts
  • • Sales Department: 100 hosts
  • • Router Link 1: 2 hosts
  • • Router Link 2: 2 hosts

Solution: Create Custom Subnets

192.168.0.0/23 (510 hosts)

HR Department (250 hosts needed)

Network: 192.168.0.0 | Broadcast: 192.168.1.255

192.168.2.0/24 (254 hosts)

IT Department (120 hosts needed)

Network: 192.168.2.0 | Broadcast: 192.168.2.255

192.168.3.0/25 (126 hosts)

Sales Department (100 hosts needed)

Network: 192.168.3.0 | Broadcast: 192.168.3.127

192.168.3.128/30 (2 hosts)

Router Link 1

Network: 192.168.3.128 | Broadcast: 192.168.3.131

192.168.3.132/30 (2 hosts)

Router Link 2

Network: 192.168.3.132 | Broadcast: 192.168.3.135

✓ Result:

Total IPs allocated: 510 + 254 + 126 + 2 + 2 = 894 (Out of 1024 available)

Wasted IPs: Only 130 (12.7%) vs 50%+ with fixed subnetting!

How to Design VLSM

1

Sort Requirements from Largest to Smallest

This prevents IP waste and ensures you have enough space

2

Allocate Subnets Largest First

Calculate prefix length for each requirement: log₂(hosts+2) = bits needed

3

Document Address Space

Track which addresses are allocated and which are available

4

Verify No Overlaps

Ensure subnets don't overlap and stay within the parent network

👤 Individual Activity: Basic Subnetting Challenge

Scenario:

Your company has been assigned the network 10.0.0.0/24. You need to create 4 equal subnets for four different departments.

Your Task:

1️⃣ Calculate the new prefix length (/##)

Hint: You need 4 subnets, so 2^n = 4, therefore n = ?

2️⃣ Calculate subnet increment

Increment = 256 ÷ (number of subnets)

3️⃣ List all 4 subnets (Network Address)

Example: 10.0.0.0, 10.0.0.64, ...

4️⃣ For Subnet 1, list the usable host range

Example: 10.0.0.1 - 10.0.0.62

✓ Correct Answers:

1. New Prefix: /26 (24 + 2 = 26)

2. Increment: 64 (256 ÷ 4 = 64)

3. Four Subnets: 10.0.0.0, 10.0.0.64, 10.0.0.128, 10.0.0.192

4. Subnet 1 Hosts: 10.0.0.1 - 10.0.0.62

👥 Group Activity: VLSM Network Design

Scenario:

Your group is the network administrator for a growing tech company. You have been assigned 172.16.0.0/21 and must design VLSM for:

  • • Main Office: 400 hosts
  • • Branch Office 1: 200 hosts
  • • Branch Office 2: 100 hosts
  • • Data Center: 50 hosts
  • • WAN Links: 4 connections (2 hosts each)

Your Group's Task:

Step 1: Sort requirements by size (largest to smallest)

Why is this important? To prevent IP address waste

Step 2: Calculate prefix length for each subnet

Use: Prefix = 32 - log₂(hosts + 2)

Step 3: Design complete VLSM allocation

Network address and prefix for each subnet

✓ Sample VLSM Design:

Main Office: 172.16.0.0/22 (1022 hosts) ← Largest first

Branch Office 1: 172.16.4.0/23 (510 hosts)

Branch Office 2: 172.16.6.0/24 (254 hosts)

Data Center: 172.16.7.0/26 (62 hosts)

WAN Link 1: 172.16.7.64/30 (2 hosts)

WAN Link 2: 172.16.7.68/30 (2 hosts)

Total used: 1022 + 510 + 254 + 62 + 2 + 2 = 1852 of 2048 hosts available
